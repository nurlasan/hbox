# Протокол устройство ↔ сервер

Вход один: `https://178.104.149.56:18443` (в облачном файрволе Hetzner открыт только этот порт).
TLS 1.2 со сертификатом Hbox (`deploy/tls/ca.crt` — его прошиваем в устройство), nginx снимает TLS
и отдаёт `/hbox/` серверу (`server/hbox_server/app.py`).

Устройство — по токену: `Authorization: Bearer <токен>`. Токены и id — `HBOX_DEVICES` в `.env`
сервера (`id:токен,...`). id — это канал в имени файла.

## Файлы с докачкой

Имя: `<канал>_YYYYMMDD_HHMMSS.mp3|m4a`, время начала по UTC.

```
GET /hbox/v1/files/<имя>
→ 200 {"size": <принято байт>, "done": <файл целый>, "check": "32768:1a2b3c4d,...,<size>:..."}
```

```
PUT /hbox/v1/files/<имя>?offset=<N>&total=<размер файла>&crc=<CRC-32 всего файла, hex>&upto=<CRC-32 начала файла по конец куска, hex>
Content-Length: <сколько байт в этом запросе>
<байты файла с позиции N>
→ 200 {"size": <принято>, "done": false|true}
→ 409 {"size": <принято>}       N не совпал с тем, что есть на сервере — продолжить с size
→ 422 {"size": 0}               CRC не сошёлся — сервер всё выбросил, слать заново с 0
→ 507                           на сервере нет места — повторить позже
→ 401 / 400                     неизвестный токен / плохое имя или параметры
```

Порядок на устройстве:
1. Файл закрыт (час кончился) — известны размер и CRC-32 (считается при записи).
2. `GET` — сколько уже есть; `done: true` — файл можно помечать отправленным.
   `check` — CRC-32 начала файла в ≤ 14 точках: 3 по всему файлу, конец последнего куска, у которого
   сошёлся `upto` (дальше — непроверенный хвост после обрыва, до 1 МБ), 8 точек в этом хвосте и `size`.
   Устройство сверяет их со своим файлом и берёт последнюю совпавшую точку: модем изредка теряет байты,
   и хвост на сервере бывает испорчен. Меньший `offset` в `PUT` отбрасывает хвост на сервере.
   Откат — не дальше проверенного места, в пределах ~1/9 хвоста от порчи.
3. `PUT` с `offset = size` кусками по 1 МБ (тело потоком через AT+MIPSEND). `upto` не сошёлся —
   сервер выбрасывает только этот кусок и отвечает 422 с `size = offset`. Между кусками устройство
   спрашивает настройки, если пора (часовой файл идёт ~30 мин).
4. Обрыв связи — ничего страшного: сервер сохранил всё, что дошло. После переподключения — снова п. 2.

CRC — стандартный CRC-32 (zlib, `esp_rom_crc32_le(0, ...)`). Сервер считает его по мере приёма,
поэтому докачка не требует перечитывать уже принятое.

## Настройки и состояние

```
GET /hbox/v1/config?rec=1&files=12&pending=0&dropped=0&overflows=0&rec_errors=0&cpu=32&csq=27
                    &up_errors=0&sent=11&kbps=54&uptime=95&reset=1
                    &sd_free=28160&sd_total=30436&pending_mb=58
→ {"record": true, "format": "mp3", "bitrate": 128000, "recheck": 300, "channel": "<id>",
   "time": "2026-11-10T09:00:00Z"}
```

Параметры запроса — состояние устройства для сайта (все числа, любые можно опустить).
`uptime` — минуты с включения, `reset` — причина последнего перезапуска (`esp_reset_reason()`).
`sd_free`/`sd_total` — место на карте, МБ (0 — карты нет), `pending_mb` — объём неотправленного, МБ.
`record` сервер считает сам по расписанию (часы работы по дням недели, Asia/Almaty) и выключателю
на сайте; `recheck` — через сколько секунд спросить снова (к ближайшей смене, не больше 300).
`time` — время сервера (UTC): по нему устройство ставит часы при каждом запросе.
Устройства, их токены и настройки — `data/devices.json`, правятся на сайте `/hbox/admin/`.

## Замер скорости

`POST /hbox/speedtest` — тело выбрасывается, ответ — строка со скоростью (hbox-xsg).

## Обновление прошивки по воздуху

Прошивка загружается на сайте (карточка устройства → «Прошивка», файл `hbox.bin` из сборки CI).
Сервер берёт из образа версию (`esp_app_desc_t`, в CI — короткий хеш коммита), кладёт его
в `data/firmware/<crc32>.bin` и назначает устройству.

Устройство шлёт с `/config` свою версию `fw` и версию, которая не запустилась, `fw_bad`. Пока `fw` не равна
назначенной (и она не `fw_bad`), в ответе есть:

```
"ota_name": "1a2b3c4d.bin", "ota_size": 530608, "ota_crc": "1a2b3c4d", "ota_version": "20ac590"
```

```
GET /hbox/v1/firmware/<ota_name>?blocks=1                  → "crc0,crc1,..." CRC-32 блоков по 32 КБ
GET /hbox/v1/firmware/<ota_name>?offset=<N>&len=<сколько>   → байты образа с N
```

Устройство берёт образ одним запросом и пишет во второй слот (`firmware/partitions.csv`) блоками по 32 КБ,
каждый — только если сошлась его CRC: модем изредка теряет байты. Испорченный блок или обрыв —
остаток запрашивается с начала этого блока (до 10 раз подряд без продвижения). Затем сверяет CRC-32 и проверку образа
ESP-IDF, переключает слот и перезагружается. Новая прошивка считается рабочей после первого ответа
сервера на `/config`; перезагрузилась раньше — загрузчик возвращает прежнюю, и та сообщает `fw_bad`.
Не вышло скачать или CRC не сошёлся — следующая попытка через 10 минут.
